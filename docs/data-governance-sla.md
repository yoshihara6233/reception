対象: Intereco Recorder Monitor（本部 Next.js on Vercel ＋ 現地エッジ ＋ Supabase）。
位置づけ: **顧客合意に用いる方針文書**。データの保持・アクセス制御・記録（監査）と、サービス水準（SLA）を定義する。

- 版: v1.0（2026-07-07・方針合意ドラフト）
- 関連: `docs/dr-runbook.md`（RTO/RPO・復旧手順）・`docs/rls-audit.md`（RLS）・`docs/security-assessment.md`

## 第1部 データガバナンス方針

### 1. 取り扱うデータの分類

| 分類 | 具体例 | 個人情報該当 | 保存先 |
|------|--------|:---:|--------|
| **映像スナップ/フレーム** | 発報前後スナップ(alarm_frames)・発報スナップ・巡回スナップ | ○（人物が写り得る） | Supabase Storage `security-snapshots`（非公開） |
| **録画クリップ(VOD)** | 区間切り出しクリップ | ○ | Supabase Storage `vod-clips`（非公開） |
| **証跡レポート(PDF)** | 巡回/BCP レポート（画像焼き込み） | ○ | Supabase Storage `reports` |
| **イベント/運用メタ** | alarm_events・patrol_runs・edge/recorder/camera 構成 | △ | Supabase DB（RLS） |
| **監査ログ** | admin_audit_log（管理操作の記録） | △（操作者ID） | Supabase DB（RLS） |
| **運用メトリクス** | metric_events（稼働率等） | × | Supabase DB |
| **管理アカウント** | admin_users（メール・ロール）・auth.users | ○ | Supabase Auth/DB |

> **映像は個人情報**（個人情報保護法上の個人データ）として扱う。取得目的は**防犯・監視の運用**に限定し、目的外利用はしない。**顔認証は行わない**（人物の有無検知まで）。
> 注: 来店者/従業員PII等の一部テーブルは基盤（reception 由来）に存在するが、本監視サービスの機能では使用しない。

### 2. 保持ポリシー（保持31日）

| データ | 保持期間 | 削除の実装 |
|--------|---------|-----------|
| 発報前後スナップ(alarm_frames)・発報スナップ | **31 日** | 日次 cron `/api/admin/vod/cleanup`（3:00） |
| 録画クリップ(vod_clips) | **31 日** | 同上 |
| 巡回(patrol_runs/findings/スナップ) | **31 日** | 毎時 cron `/api/cron/security-patrol` |
| 証跡レポート(PDF) | **恒久**（長期証跡） | 削除しない（画像焼き込み済み） |
| 運用メトリクス(metric_events) | 90 日 | `/api/cron/edge-health` |
| 監査ログ(admin_audit_log) | 恒久（当面） | — |

- **保持31日**: 映像・録画・巡回の生データは **31 日で自動削除**（Storage オブジェクト＋DB 行）。削除は Storage 削除成功後に DB 行を消す方式で、失敗時は次回再試行（消し漏れ・孤児を防ぐ）。
- **長期に残すのは PDF レポート**（人が確認済みの証跡）。生画像は31日で消える設計＝「長期証跡は PDF」。
- 実装定数: `DEFAULT_TTL_DAYS=31`（vod cleanup）・`PURGE_DAYS=31`（patrol）。方針変更時はここを更新。

### 3. アクセス制御

- **認証**: Supabase Auth（メール＋パスワード）。パスワードは bcrypt ハッシュ、リセットはメール経由（OTP をブラウザに露出しない設計）。
- **認可（テナント/店舗スコープ）**: 全テーブルに **RLS** を適用（本番46テーブル全 RLS 有効）。`admin_users.auth_user_id = auth.uid()` を基点に、super_admin=全テナント / tenant_admin=自テナント / 店舗スコープでフィルタ。
- **映像配信は必ず認証プロキシ経由**: Storage の署名 URL は本部 API がセッション認証＋RLS 判定後に発行。エッジ/カメラを直接インターネット公開しない（リモート視聴は Cloudflare Tunnel＋Access の許可メールのみ）。
- **鍵管理**: service_role 等の秘密は Vercel env / エッジ `agent.env`（systemd EnvironmentFile）で管理。漏洩時は無停止ローテ手順あり（`dr-runbook.md` §5.4）。レコーダ認証情報は Vault で暗号化。

### 4. アクセス記録（監査）

- **管理操作の記録（実装済み）**: `admin_audit_log` に、レコーダ/カメラ/エッジ/エンロール/OTA 等の**作成・変更操作**を記録（操作者 `actor_user_id`・`action`・対象・`store_id`・変更内容 `changes`・時刻）。秘密値はマスクして記録。RLS で自テナント分のみ閲覧可。
- **映像閲覧アクセスの記録（実装済み）**:
  - **ライブ / グリッド / VOD の閲覧**: `live_sessions`（ユーザ・店舗・カメラ・モード・開始/終了・継続時間）。`/admin/audit` で閲覧。
  - **証跡静止画のアクセス**: `footage_access_log`（発報スナップ / 発報前後フレーム / 巡回スナップ / BCPエクスポート）。ユーザ・店舗・種別・対象・時刻を記録し、**5分バケットで重複排除**（ポーリング/再描画の膨張防止）。`/admin/audit` の「証跡静止画アクセス」セクションで閲覧（ライブ/VOD と同一ページ）。保持180日。
  - RLS: super_admin=全件 / tenant_admin=自テナントの店舗由来のみ。
- 監査ログの保持: 管理操作は恒久・映像閲覧は180日。改ざん防止（追記のみ）は今後の強化候補。

### 5. プライバシー・セキュリティ措置（要約）

- 保存時暗号化: Supabase（DB/Storage）の保存時暗号化に準拠。通信は TLS。
- 最小権限: RLS＋ロールで越権参照を防止。エッジは device_token＋（移行中）スコープトークンで最小権限化。
- データ最小化: 生画像は31日で自動削除。顔認証・個人特定処理は行わない。
- 第三者提供: 行わない（AI 二次判定を将来オプションで使う場合は店舗単位 opt-in＋本書に追記）。

## 第2部 SLA 定義書

### 6. サービス可用性

| 項目 | 定義 |
|------|------|
| **可用性目標** | 本部クラウド（監視画面・API）で **月間 99%**（許容ダウンタイム 約 7.2 時間/月） |
| 測定対象 | `https://intereco-monitor.vercel.app` の応答性（クラウド面）。個別エッジ/カメラ/店舗網の障害は対象外（別掲）。 |
| 測定方法 | 死活監視 cron（2分毎）＋Vercel/Supabase 稼働。計画メンテは除外。 |

### 7. 復旧目標（RTO/RPO）

`docs/dr-runbook.md` に準拠。要点:

| 対象 | RTO | RPO |
|------|-----|-----|
| アプリ(Vercel) | < 15 分 | 0（git） |
| DB スキーマ | < 30 分 | 0（git baseline・訓練実績28秒） |
| DB データ | 1〜4 時間 | **≤ 1 時間**（毎時外部バックアップ・2026-08-06〜） |
| エッジ1台 | 2〜4 時間 | 該当店のライブ/巡回/発報のみ |

> **RPO（データ）は ≤1 時間**。毎時 `pg_dump --data-only` を Cloudflare R2 へ外部保管している
> （取得＝GitHub / 保管＝Cloudflare / 本番＝Supabase の三点をベンダ分離）。
>
> ⚠ **秒単位の RPO を合意する場合は Supabase PITR（有料）が必要**。当社は
> **2026-09-30 を期限**として有効化予定（Phase D の実店舗展開＝実証跡が入る前）。
> PITR は遡って効かないため、この期限は前倒しはできても後ろ倒しにはしない（`dr-runbook.md` §6.0）。

### 8. サポート・エスカレーション

- 検知: エッジ/トンネル断は死活監視が**メール＋Webhook 通知**（障害から約5分以内）。
- 一次対応→二次対応→外部（Supabase/Vercel/Cloudflare）の流れは `dr-runbook.md` §7。
- 対応時間帯・連絡先・目標応答時間は**顧客契約で個別合意**（本書は枠組みを定義）。

### 9. 対象外・免責

- エッジ機/カメラ/店舗 LAN・電源・インターネット回線の障害（現地設備）。
- 外部サービス（Supabase/Vercel/Cloudflare/LiveKit）起因の広域障害。
- 計画メンテナンス（事前告知）。
- 顧客側の設定変更・認証情報管理不備に起因する事象。
